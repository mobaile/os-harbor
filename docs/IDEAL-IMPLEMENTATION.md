# 理想目标：每套系统都拥有一块只属于自己的硬盘

> **第二版功能愿景 · 2026-09-11。本文描述希望最终实现的完整体验，不是已实现能力。具体技术路线留给后来者探索。**

我们把这个想法公开记录下来，希望有类似需求的人能够找到它，有实现能力的人能够从中获得方向，协助他们的 AI 工具也能理解这个需求并参与研究。

这份愿景不以当前产品、接口或相近技术的能力作为上限。它先回答“最终应该是什么样”，把“如何实现”留给后续的工程探索。

## 1. 一个分区，就是一套完整系统

用户在真实硬盘上为一套系统划定一个专用分区。这段空间直接保存完整磁盘内容，包括该系统自己的分区表、引导、操作系统和用户数据。

从外部看，它是一个承载分区；从内部看，它就是一块独立完整硬盘。比如分配 200GB，系统看到的就是一块容量为 200GB、地址从零开始的硬盘，而不是某块更大硬盘上的一个受限分区。

```text
外部管理者看到                         Linux 看到

真实硬盘                              一块完整的 200GB 硬盘
├── Windows 与现有数据                 ├── 自己的分区表
├── Linux A 承载分区：200GB ─────────→ ├── 自己的引导分区
└── 其他系统的承载分区                 └── 自己的系统和数据分区
```

正常安装和运行直接读写这个承载分区，不需要先创建一个用来保存系统的文件。一个系统从安装到使用始终对应同一份磁盘内容。

## 2. Linux 不知道自己被隔离

系统始终只发现自己的完整硬盘，不发现外层分区表、其他硬盘或其他系统的承载空间。安装器、引导器、内核、桌面和磁盘管理工具获得一致的磁盘视图。

系统正常工作即可，不需要安装项目专用驱动、服务或 hook，不需要理解外部布局，也不需要通过受限账户来主动遵守边界。

这块硬盘内部的管理权限完整保留：可以创建和删除分区、格式化、重装系统、安装引导和更新内核。无论内部如何管理磁盘，都不能把访问范围扩展到外面。

## 3. 安装和使用都应像独占一台电脑

1. 用户在 Windows 中选择要安装的系统、原版安装介质和准备分配的空间。
2. 电脑重启，安装器只看到为这套系统准备的完整硬盘，按正常流程安装。
3. 系统的引导文件和所有内部磁盘操作都落在自己的承载范围内，Windows 的原有分区和引导保持完整。
4. 后续在 Windows 中选择这套系统并重启，即进入它的正常桌面；Windows 此时不运行。
5. 系统使用自己的原版内核及真实硬件，正常更新、关机、重启和管理内部存储。
6. 下一次没有主动选择其他系统的正常开机，仍直接进入 Windows。

整个过程不要求用户反复调整 BIOS 启动顺序、修复 Windows 引导，或手工配合磁盘映射。系统的引导配置变化应只影响自身，不夺走 Windows 的永久默认启动地位。

## 4. 完整体验应同时满足哪些条件

| 场景 | 理想结果 |
|---|---|
| 原版安装器枚举磁盘 | 只显示属于当前系统的完整硬盘 |
| 内核接管硬件 | 磁盘视图与安装和引导阶段一致，外部空间不暴露 |
| 管理员执行“清空整盘” | 只清空自己的承载分区，Windows 和其他系统不受影响 |
| 系统升级、更换发行版内核或重装 | 不需要向内部系统注入项目适配，隔离始终成立 |
| 磁盘重新扫描、设备复位、睡眠后恢复 | 独立容量与访问边界保持一致 |
| 安装器更新引导配置 | 本系统可以正常启动，Windows 默认地位保持不变 |
| 内部空间写满或文件系统损坏 | 影响局限于当前系统，不波及其他承载空间 |
| 断电或启动失败 | 外部系统数据与引导不被破坏，用户有清晰的恢复入口 |
| 管理器离线备份或恢复 | 完整保留或还原该系统磁盘内容，不要求内部系统参与 |
| 移除某套系统 | 回收它的承载空间，不改变其他系统的内容 |

这些是最终功能目标，不是当前测试结果。正常裸机性能、硬件功能和系统管理能力也属于目标的一部分，不应靠牺牲这些体验来换取表面上的隔离。

## 5. 对实现方式的期待

理想中，在操作系统开始安装或运行之前，就已经为它准备好独立完整的磁盘环境。此后即使固件把机器交给操作系统、系统加载自己的驱动或重新发现设备，这个环境也一直成立。

固件可以成为选择系统和准备环境的入口，存储硬件或未来机制可以参与维持边界。这里不指定必须由哪一层完成，也不预设现有主板 BIOS、某种控制器或某个标准必须已经支持它。

最终实现应保留以下要求：目标系统裸机运行、使用自己的原版内核、不修改内核源码、不依赖虚拟机或容器、系统内部无需项目专用组件。具体工作由哪些外部机制承担，留给实现者决定。

如果今天的接口不足以承载这个目标，可以提出新的接口、固件能力、存储硬件设计或其他满足要求的机制。已有方案可提供线索，但不代替目标本身。

## 6. 留给后来者的工作

如何呈现唯一磁盘、如何让访问边界持续成立、如何保持完整管理权限、如何衔接引导和恢复，以及如何让不同硬件与发行版获得一致体验，都是后续可以继续解决的问题。

有用的贡献可以从需求讨论、接口设计、硬件研究或原型开始。阶段性成果应如实说明完成了哪一部分；完整愿景继续保留，不因为某一种现有方法做不到，就改成另一种较弱的体验。

我们希望最终得到的是：**用户用一个分区管理一套系统，而这套系统从安装到运行，都像拥有一块完全属于自己的硬盘。**
