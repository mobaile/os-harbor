# 第二版技术依据与研究边界 · 2026-09-11

> **本次为官方资料审查与设计整理，未执行分区映射、安装、启动或固件修改。组件文档只证明对应机制存在，不证明 OS Harbor 的完整组合可用。**

目标与约束见[第二版构想](CONCEPT.md)，实际检查记录见[VALIDATION](VALIDATION.md)。

## 1. 分区作为完整磁盘的存储后端

[dm-linear 官方文档](https://docs.kernel.org/admin-guide/device-mapper/linear.html)描述了块设备区域之间的线性映射。这为“物理承载分区 → 独立块设备视图”提供基础，无需先创建外层文件系统和 RAW 文件。

据此可以提出第二版的布局：在映射设备的范围内存储内部 GPT、EFI 和 Linux 分区。此处是设计推导；文档没有证明具体安装器会接受这种设备，也没有证明嵌套分区识别、扇区尺寸和全部磁盘命令都满足目标要求。

[targetcli 官方手册](https://raw.githubusercontent.com/open-iscsi/targetcli-fb/master/targetcli.8)分别记录了 BLOCK 后端与 LOOPBACK：前者使用本地块设备，后者可把存储对象重新呈现为本机 SCSI 设备。因此，“承载分区 → LIO BLOCK → 本地 SCSI 设备”可列为另一项研究候选。这里不运行虚拟机；是否适合安装和根设备启动，尚无本项目实验结果。

两种候选都不应被描述为已经选定的实现。设备类型、模块依赖、分区发现、写入一致性和异常路径需单独验证。

## 2. 映射与透明隔离的证据缺口

映射为目标设备提供了地址范围，但后端原始盘仍需要由内核访问。由上述接口无法推出“原始盘不再可见”或“原版 Linux 无法绕过映射”。

| 所观察到的能力 | 不能据此推断的结论 |
|---|---|
| 映射设备只包含指定范围 | 原始整盘、其他分区和控制器入口均不可访问 |
| 安装器显示了一个目标设备 | 系统的其他发现或访问路径已被隔离 |
| 普通读写落在承载分区内 | 原始命令、重新扫描或修改映射不能绕过边界 |
| 从映射根设备进入桌面 | 整套 Linux 无感地只拥有这一块磁盘 |

第二版要求保留原版目标内核和正常系统行为，且不采用虚拟机或容器路线。当前没有满足这些约束的完整透明隔离机制。此缺口来自第一版也未完成的工作，不会因文件后端换成分区自动消失。

## 3. 早期启动与内层引导

[内核早期映射文档](https://docs.kernel.org/admin-guide/device-mapper/dm-init.html)提供两种根设备准备方式：早期用户空间建立映射，或在具备相应功能的内核中通过启动参数创建映射。这说明映射可纳入目标内核启动阶段，不能说明跨内核交接时映射会自动继承。

候选设计仍需处理内层 GPT、根设备定位、加密层和目标内核模块；外部适配必须与所用内核及启动框架相符。不修改目标内核源码不等于任意发行版的内核都具备所需配置。

内部 EFI 分区位于承载分区中，不能假定真实固件会递归解析并直接启动它。外部启动入口、启动资料提取和目标内核加载如何衔接，是另一个未实现环节。仅能读取这些资料不等于已经能够启动系统。

## 4. Windows 默认项与关机

[UEFI 2.11 Boot Manager 规范](https://uefi.org/specs/UEFI/2.11/03_Boot_Manager.html)规定 `BootNext` 指定下一次尝试的启动项，并在交接给该项之前清除。这为保留正常启动顺序、临时选择独立入口提供依据。

它不保证安装器不会改写 `BootOrder`，不负责发现嵌套 EFI，也不构成目标系统启动后卡死的自动恢复机制。Windows 入口的设置、权限、真实固件行为和失败返回均待验证。

[systemd initrd 接口](https://systemd.io/INITRD_INTERFACE/)说明了通过 `/run/initramfs/shutdown` 返回早期环境进行清理的能力。可以研究从外部准备对应环境，完成内部文件系统、加密层和映射的有序释放；本项目尚未实现或测试这一组合。

第二版不再为了访问系统文件保留外层文件系统，但内部持久化、设备同步、清理失败和连续冷启动仍需单独验证。

## 5. 安装器兼容与证据版本

承载分区可提供块存储，不意味着原版安装器接受它的名称、类型和内部布局，也不意味着引导写入与安装完成检查可直接通过。

第一版在 2026-09-10 对 Omarchy 安装器提交 `a23f8d464dcb0616a61bfaa8026e23d0533da209` 做过源码审查，记录了设备筛选和 EFI 写入相关限制。原始内容保存在[第一版技术依据](history/v1/FEASIBILITY-EVIDENCE.md)；该审查不能作为当前发布 ISO 或第二版分区后端的验证结果。

后续实验需固定 ISO 来源和 SHA-256、安装器及依赖版本、目标内核、硬件和映射方式，并取得非目标分区、外层分区表、Windows 引导文件及固件变量的前后证据。本次没有新增安装器源码审查或实机证据。

## 6. 结论的适用范围

资料支持继续研究分区后端与早期启动适配，并支持“省去文件后端依赖”的结构判断。没有证据可将它提升为透明隔离、原版安装、性能等同裸机普通分区或稳定生命周期的保证。

本项目与引用的内核、发行版及工具项目没有隶属或背书关系。所有尚未执行的实验均在[验证记录](VALIDATION.md)中保持待验证状态。
