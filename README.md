# OS Harbor · 方案 v2：一个分区承载一套系统

> **这是未经端到端验证的多系统管理构想，不是可用的安装或启动工具。分区映射具有现成技术依据，但透明隔离、原版安装、裸机启动及完整生命周期尚未验证。方案版本不代表软件发行版本。**

**Unverified concept, not a working installer or boot manager.** Concept v2 uses a dedicated physical partition to hold an entire system disk. Transparent isolation and end-to-end bootability have not been demonstrated.

## 想实现的体验

平时电脑默认进入 Windows。需要另一套系统时，在 Windows 管理入口选择它并重启，Windows 停止运行，由所选 Linux 使用自己的内核在真实硬件上运行。

**外面是一个专用物理分区，里面是一套完整的系统磁盘。** 安装器和 Linux 理想中只看到一块属于自己的完整硬盘，能够正常分区、格式化、安装引导和读写数据，无需知道这块“硬盘”实际来自另一块硬盘上的一个分区。

这是一项目标，不是已实现的设备隔离保证。

## 核心结构

```text
物理硬盘
├── Windows 分区与原有引导
├── 系统 A 的承载分区
│   └── 完整磁盘内容：内部 GPT → EFI 分区、Linux 根分区、数据
└── 系统 B 的承载分区
    └── 完整磁盘内容：内部 GPT → EFI 分区、Linux 根分区、数据

外部启动／维护环境（待实现）
└── 选择承载分区 → 提供完整磁盘视图 → 安装或启动目标系统
```

- 每套系统使用一个专用物理分区，直接读写其块空间，不再通过外层文件系统中的系统文件存储。
- 同一承载分区贯穿安装和运行，内部保留自己的分区表、引导文件、系统和数据。
- 目标系统使用自己的内核，不修改目标内核源码，不采用虚拟机或容器路线；项目适配放在系统外部。
- Windows 保持默认启动地位，管理入口仅提交一次性启动请求；内层引导与真实固件入口的衔接仍需研究。
- 备份、恢复和容量管理围绕承载分区进行，不能再把删除或复制一个文件直接等同于移除或备份系统。

## 技术依据与未解决的问题

Linux 的 [dm-linear](https://docs.kernel.org/admin-guide/device-mapper/linear.html) 支持将块设备的一段区域映射成另一个块设备，为分区作为存储后端提供基础。早期启动也有[建立映射设备的机制](https://docs.kernel.org/admin-guide/device-mapper/dm-init.html)。

**增加一个映射设备，不会自动隐藏原始硬盘，也不会自动阻止绕过映射的访问。** 本方案最关键的透明隔离问题仍未解决；不能将设备映射、隐藏安装列表或一次成功启动当成它已成立的证据。

| 已有依据或结构上的简化 | 仍待验证 |
|---|---|
| 用物理分区替代系统文件，省去外层文件系统和文件映射依赖 | Linux 无感地只获得指定磁盘视图，其他分区不可访问 |
| 块设备区域映射与早期根设备准备有标准机制 | 原版安装器接受设备并完成分区、引导和安装检查 |
| UEFI 一次性启动请求有标准机制 | Windows 默认项保护、内层 EFI 接入与失败返回 |
| 系统状态可按整个承载分区保存 | 冷启动、关机、内核更新、恢复及硬件兼容性 |
