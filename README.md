# OS Harbor：把系统当作一个文件来管理

> **这是一个未经端到端验证的多系统管理构想，不是可用的安装或启动工具。核心的裸机安装、单文件启动及系统兼容性均未验证。仓库中的代码仅为早期实验，不应直接用于重要设备。本项目仅供思路交流与参考，目前没有继续开发计划。**

**Unverified concept, not a working installer or boot manager.** Bare-metal installation, image boot and compatibility have not been validated. The code is an early experiment, shared for reference and inspiration. No further development is currently planned.

## 为什么留下这个项目

多系统安装通常意味着为每个系统划分空间、处理引导和承担恢复成本。这里想探索另一种体验：保留现有主系统，把其他系统当作文件来安装、选择、备份和移除。

理想状态是：**安装器眼里是一块硬盘，用户眼里始终是一个文件。** 本文讨论这一体验的架构与可行性边界，不绑定某个具体系统或发行版，也不意味着任意系统都能使用这条路线。

## 核心思路

- 现有主系统保持原有安装方式，并作为默认启动系统。
- 目标系统共用一个镜像仓库，不为每个系统单独划一个物理分区。
- 每个目标系统对应一个标准 GPT RAW 磁盘文件，包含自己的引导资料、根文件系统和用户数据。
- 裸机安装环境将 RAW 映射为块设备，让原版安装器直接安装进去；以后从**同一文件**裸机运行。
- 外部环境负责存储映射、早期启动适配和必要的关机清理；镜像内部不安装项目专用驱动、服务或 hook。
- 管理入口提交维护任务和一次性启动请求；备份、克隆和恢复围绕离线 RAW 文件进行。

```text
物理磁盘
├── 现有主系统与原有引导
└── 公共镜像仓库
    └── systems/
        ├── system-a.raw
        ├── system-b.raw
        └── system-c.raw

独立引导／维护环境
└── 识别所选镜像 → 加载目标内核 → 重建存储映射 → 进入目标系统
```

“一个文件”指完整系统状态保存在 RAW 中。引导环境、任务索引、日志和可重建的启动缓存仍在外部；这不意味着固件天然可以直接运行任意磁盘文件。

## 可行性与当前边界

**核心存储与启动方向有技术依据，值得开展限定范围的原型验证；完整方案尚未证明可用。** 当前查证的机制只覆盖部分内核、存储接口和启动框架，不能据此推出对任意操作系统的支持。

| 层次 | 判断与边界 |
|---|---|
| 基础能力 | 已有文件到块设备、早期存储准备、内核交接与关机清理机制，可作为候选架构的组成部分。 |
| 安装兼容 | 设备能被映射，不代表原版安装器接受它；还必须验证分区、引导写入、权限边界和完成检查。 |
| 运行可靠性 | 能进入系统只是起点，还要证明写入持久化、关机、冷启动、更新和缓存重建可靠。 |
| 镜像独立性 | 标准格式与外置适配有助于减少持久依赖，但不保证跨硬件迁移或任意工具直接启动。 |
| 产品化范围 | 多系统兼容、异常恢复、容量管理及主系统保护，需要持续维护和实机证据。 |
| 项目实现 | 现有代码是较早路线的管理实验；当前 RAW 架构的核心链路尚未实现。 |
